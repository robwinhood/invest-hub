# ADR-005: 단일 모듈 선택 (멀티모듈 미사용)

## 상태

확정 (2026-05-31)

## 맥락

헥사고날 아키텍처를 강제하는 방법은 두 가지다:
1. **패키지 구조** + ArchUnit 테스트로 경계 강제
2. **멀티모듈 Gradle** 프로젝트로 컴파일 수준에서 경계 강제

## 결정

**단일 모듈**을 선택하고, 아키텍처 경계는 ArchUnit이 빌드 시 강제한다.

## 이유

1. **범위**: 단일 서비스·단일 기능이다. 멀티모듈이 빛을 발하는 시나리오(여러 팀이 독립적으로 배포하는 대규모 시스템)가 아니다.

2. **빌드 복잡도**: 멀티모듈은 모듈 간 의존성 선언, 공유 설정 관리, 빌드 캐시 설정 등 추가 복잡도가 생긴다. 단일 서비스에서 이 비용을 감수할 이유가 없다.

3. **ArchUnit으로 충분**: `HexagonalArchitectureTest`가 동일한 경계를 테스트 수준에서 강제한다. 컴파일 수준 강제가 필요할 만큼 팀이 크지 않다.

4. **POC 성격**: 이 프로젝트는 실무 도입 전 검증 목적이다. 과도한 구조화보다 핵심 개념 증명이 우선이다.

## 결과

- `settings.gradle.kts`는 단일 루트 프로젝트만 선언한다.
- 경계 위반은 ArchUnit(`HexagonalArchitectureTest`)이 빌드에서 잡는다.
- 향후 서비스 규모가 커지고 팀이 분리되면 멀티모듈로 전환을 검토한다. 그 시점의 기준: 독립 배포가 필요하거나 두 팀 이상이 동일 레포를 관리하는 경우.
